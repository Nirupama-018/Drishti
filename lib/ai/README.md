# Member 1 — AI/ML & Adaptive Personalization

## Overview

I am responsible for the **AI/ML and adaptive personalization layer** of Cognitive Care.

The purpose of this module is to make the cognitive training system **adaptive rather than fixed**.

Instead of giving every patient the same game at the same difficulty, the AI layer uses previous game performance to determine:

* Which cognitive game should be played next
* What difficulty level should be used
* Whether the patient's performance is improving, stable, or declining
* Which cognitive domain currently needs more attention
* What game configuration should be given to the game

### Core idea

```text
Patient
   ↓
Cognitive Game
   ↓
Game Result
   ↓
Performance Analysis
   ↓
Cognitive Profile
   ↓
Adaptive Engine
   ↓
Next Game + Difficulty
   ↓
Patient
```

The system is intended for **personalized cognitive training and longitudinal monitoring**.

It is **not a dementia diagnosis system** and the scores generated by this module should not be interpreted as clinical diagnoses.

# 7. Performance Analysis

`PerformanceAnalyzer` converts a `GameResult` into performance metrics.

Current metrics:

```text
accuracy
errorRate
missRate
falseSelectionRate
speedScore
completed
```

### Accuracy

```text
correct / totalTargets
```

### Error rate

```text
incorrect / totalTargets
```

### Miss rate

```text
missed / totalTargets
```

### False selection rate

```text
incorrect / (correct + incorrect)
```

### Speed score

Currently:

```text
1 / (1 + responseTime)
```

This is an initial normalized score and is **not a clinical measurement**.

It may be improved later with difficulty-aware normalization.

# 8. Cognitive Profile

The AI maintains a multidimensional cognitive profile.

Current domains:

```text
Visual Memory
Selective Attention
Processing Speed
```

Each domain contains:

```text
performance

```

Example:

```text
Visual Memory
    performance: 0.78
    trend: 1.0
    confidence: 1.0

Selective Attention
    performance: 0.62
    trend: 0.5
    confidence: 0.75
```

These values are internal AI values and **must not be displayed to the patient as medical/clinical scores**.

# 9. Baseline

The current baseline is based on the average accuracy of completed results.

For example:

```text
Session 1 → 60%
Session 2 → 80%
Session 3 → 70%
Session 4 → 90%

Baseline = 75%
```

The baseline is intended to represent the patient's own performance rather than comparing the patient against another patient.

This allows the system to support **patient-specific longitudinal tracking**.

---

# 10. Trend Detection

The AI currently requires at least **4 completed observations** before determining a trend.

The observations are divided into:

```text
Earlier observations
        vs
Recent observations
```

Current rules:

```text
recent - earlier > 0.05
        → Improving

recent - earlier < -0.05
        → Declining

otherwise
        → Stable
```

If there are fewer than 4 observations:

```text
Insufficient Data
```

This is a performance trend and **not a diagnosis**.

---

# 11. Confidence

Confidence represents how much data the AI has available for a cognitive domain.

Current rule:

```text
0 observations → 0.00
1 observation  → 0.25
2 observations → 0.50
3 observations → 0.75
4+ observations → 1.00
```

The purpose is to prevent the system from making aggressive decisions based on very little data.

---

# 12. Difficulty Adjustment

The adaptive engine currently uses three difficulty levels:

```text
Level 1
Level 2
Level 3
```

### Increase difficulty

If:

```text
performance >= 80%
AND
trend >= 0.5
```

then:

```text
difficulty + 1
```

### Decrease difficulty

If:

```text
performance < 50%
```

then:

```text
difficulty - 1
```

### Otherwise

Keep the current difficulty.

Difficulty is always clamped between:

```text
1 and 3
```

The system therefore cannot accidentally generate:

```text
Level 0
Level 4
```

---

# 13. Game Selection

The AI chooses the next game based on the cognitive profile.

The basic strategy is:

```text
If one cognitive domain is weaker
        ↓
prioritize that domain
```

For example:

```text
Visual Memory       55%
Selective Attention 82%

             ↓

Next game:
visual_memory
```

If there is insufficient data for a domain, the system can select that game to collect more information.

If both domains have insufficient data, the system alternates between games.

If both domains have enough data and similar performance, the system alternates rather than repeatedly selecting the same game.

# 14. Adaptive Controller

The main orchestration component is:

```text
lib/ai/adaptation/adaptive_controller.dart
```

It performs:

```text
GameResult
    ↓
Add completed result to history
    ↓
Build CognitiveProfile
    ↓
Ask AdaptiveEngine for next decision
    ↓
Return AdaptationDecision
```

Usage:

```dart
final decision = controller.processResult(result);
```

The returned `AdaptationDecision` contains:

```text
gameId
difficultyLevel
memoryConfig
attentionConfig
```

Incomplete/abandoned results are not added to the completed-session history.

# 24. Current Limitations

The current AI is intentionally a **working adaptive prototype**, not a clinical AI system.

Current limitations include:

### Processing Speed

`processingSpeed` currently has no real profile data.

```text
confidence = 0
```

This can be expanded when sufficient game metrics are available.

### Speed Score

The current speed score is:

```text
1 / (1 + responseTime)
```

It is a simple normalization and should eventually become difficulty-aware.

### Persistence

`SessionHistory` is currently in-memory.

Closing the application loses the current history.

A persistent database/backend layer can be added later.

### Timestamps

`GameResult` currently does not contain a timestamp.

Longitudinal storage can later wrap results with session timestamps without changing the current game-result contract.

### Clinical Interpretation

The current profile is intended for:

```text
personalization
training adaptation
performance tracking
```

It must not be presented as:

```text
diagnosis
medical score
dementia severity score
clinical assessment
```

# 26. Design Principle

The main principle of this module is:

> **Games collect performance data. AI interprets the data. The adaptive engine decides what should happen next. UI displays and launches that decision.**

Therefore:

```text
Game
    ≠
AI

AI
    ≠
UI

AI provides the decision.
UI executes the decision.
Game provides the result.
```

This separation allows all five members to work in parallel while minimizing conflicts.
